# O12 BPB 算术共享专项

`verify.py --tool-dir <Icarus bin目录>` 使用当前5个挂载模块，和 `reports/bpb_share_20261019/before/worktree/rtl` 的冻结 S1 基线比较。冻结模块及其相互引用全部重命名，不会意外引用候选实现。

测试通过需同时满足两个相互补充的条件：

- 每一时钟比较 `fat32_card_catalog` 的全部 **339 位公开输出**，包括复位、开始前后、挂载中间元数据、`found_valid` 的暂存结果、完成脉冲以及空闲保持；不屏蔽无效期元数据。
- 使用独立构造的完整512字节扇区，检查每次 LBA 请求顺序、每项 BMP 的索引/首簇/大小、最终 FAT/数据/根目录地址、簇数、SPC、WAV 和错误状态。预期不读取 DUT 的算法或解析寄存器。

默认6组配置：超时参数2048、8192、实际50000000，各配1张或4张 BMP，并在同一次目录扫描中找到 WAV。每组47次开始：21次成功、23次错误完成、3次传输中复位中断。正常扇区全部按512字节运行，不缩短文件或删减协议字段。

覆盖的关键分支包括：

- SF→MBR→SF 无复位切换，SPC/FAT大小/根簇/活动 FAT 不同；上次元数据空闲保持和重新开始时各字段的原始更新时间。
- superfloppy 优先，即使同一扇区含 `EE`；MBR 首个结构合法 `0B/0C` 优先，忽略活动标记的优先级，跳过坏状态和溢出候选；分区末端恰好 `2^32` 可通过，任何 `EE` 拒绝 MBR 回退。
- BPB 超过分区长度、FAT容量不足、根簇越界和首候选 BPB 失败后不尝试后一个分区。
- LBA0、正式 BPB 和目录三阶段真实 CRC/status 错误；短、错序、额外字节；`rd_done` 与 byte511 同周期；输入间隙、ready 等待、忙时 start。
- 短包或早 CRC 错误后，probe/formal 两个前端仍 busy 的分支有显式到达计数，立即无复位复扫，并验证原有错误和后续恢复过程；不是遇到错误就复位后宣称恢复已覆盖。
- 定位器、正式 BPB、目录各自的超时；三阶段传输中复位后重扫。

2048、8192 的超时自然运行。仅50000000的三个故意空等超时分别在双方对应外层计数器置入 `LIMIT-2`，缩短无数据等待；不改变普通扇区、字段、状态机、接收计数、数据通路或输出比较。这证明实际参数的终端比较与优先级，不冒充自然等待5000万拍测试。

现有协议边界如实保留：正式 BPB 前端在有序 byte511 已完成之后忽略多余字节，因此这一特定用例按既有成功行为验收；LBA0定位器和目录自身另有传输计数，拒绝相同额外字节。此专项没有修改这项旧行为，也不把它算作正式 BPB 的额外字节拒绝覆盖。

`fault_injection.py --tool-dir <Icarus bin目录>` 只在临时副本中注入共享owner固定、丢失分区偏移、丢失活动FAT选择、取消FAT容量检查四类故障，必须全部被上述 oracle 拒绝。实际生产 RTL 不受修改。

结果保存在 `summary.json`、`regression.log`、`fault_injection.json`、`fault_injection.log`，含精确源文件 SHA256。测试是扇区接口级模拟，不等同于真实 TF 卡、SDRAM 或上板验收。
