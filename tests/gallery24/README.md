# 太阳系特展：24 图容量验收

生产顶层 `hdmi_media_board_top` 设定 `MAX_IMAGES=24`，索引和计数均为 5 位。
下层仍可显式配置最多 32 项，保留旧通用回归，不影响当前 24 项产品上限。
图片目录 RAM 随 `MAX_IMAGES` 实际声明为 24×64 位；不把声明位数减少视为实际 BRAM 或 Slice 节省。

运行：

```powershell
python -B tests/gallery24/verify.py --tool-dir 'Icarus Verilog 的 bin 目录'
```

脚本使用真实 FAT32 挂载、目录、文件、BMP 解码、双缓冲和预读控制器，复用独立构造的扇区字节与像素预期。

- 输入 0、1、6、23、24、25、32 张图；只接收前 24 张，逐槽验证真实解码像素。
- 目录 RAM 的实际声明深度必须等于配置容量；索引 31 不得读取过期元数据或发起文件读取。
- 下一张、上一张、末尾回绕、自动轮播，以及读取期间的音频扇区并发。
- 坏 BMP 与 CRC 重试失败不得替换当前完整画面。
- 图片已满后仍继续寻找音乐：目录中先放 32 张 BMP，再放 0～5 首 WAV，最多保留 4 首；覆盖噪声目录项、CRC 和字节顺序错误。
- 素材预检默认接受 24 BMP＋4 WAV；25 BMP、5 WAV 或旧单曲配置不符合时拒绝。

结果保存在本目录 `summary.json` 与 `regression.log`。这是逻辑和素材格式验收，不代替 TD 综合、布线、时序与实际板卡验收。
